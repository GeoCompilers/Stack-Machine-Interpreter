# Компилятор исходного языка

Компилятор переводит программу в синтаксисе из задания в JSON-массив инструкций,
который принимает `cmd/sm`. Входом является текст программы с внешним блоком
`{ ... }`, результатом — инструкции `READ`, `WRITE`, `CONST`, `LD`, `ST`,
`BINOP`, `LABEL`, `JMP`, `JZ` и `JNZ`.

## Сборка и запуск

```text
make build-compiler
./compiler.exe -source program.l0 -output code.json
./main.exe -code code.json -input input.txt
```

Без параметра `-output` JSON выводится в стандартный вывод:

```text
./compiler.exe program.l0 > code.json
```

## Этапы работы

1. Лексер преобразует текст в токены: идентификаторы, константы, операторы и
   пунктуацию. Он пропускает пробельные символы, `--`-комментарии и вложенные
   `(* ... *)`-комментарии.
2. Парсер строит внутреннее синтаксическое дерево. Он проверяет структуру
   операторов и выражений, необязательные точки с запятой, приоритеты и
   ассоциативность бинарных операций.
3. Генератор обходит дерево и формирует инструкции. Выражение оставляет одно
   значение на стеке; оператор `write` снимает его со стека, а присваивание
   записывает в память машины.

Например, исходная программа:

```text
{x=2; y=3; write(x*y);}
```

создаёт программу:

```json
[
  {"CONST": 2},
  {"ST": "x"},
  {"CONST": 3},
  {"ST": "y"},
  {"LD": "x"},
  {"LD": "y"},
  {"BINOP": "*"},
  "WRITE"
]
```

## Файлы

### `cmd/compiler/main.go`

Это оболочка командной строки. Она читает файл из `-source`, вызывает
`compiler.Compile`, затем печатает JSON или сохраняет его в путь из `-output`.
Поддерживаются также один или два позиционных аргумента: исходник и,
необязательно, путь результата. Здесь же находятся сообщения об ошибках
чтения, компиляции и записи файла.

### `internal/compiler/compiler.go`

Это публичная точка входа пакета — функция `Compile`. Она последовательно
вызывает `lex`, парсер и генератор, после чего сериализует список инструкций
через `json.MarshalIndent`. В случае ошибки лексера или парсера JSON не
возвращается.

### `internal/compiler/token.go`

Здесь определён тип токена и его категории: конец входа, идентификатор, число
и символ. Файл содержит небольшие функции для проверки допустимых частей
идентификатора, цифр и пробелов, а также функции форматирования позиции токена
в диагностике.

### `internal/compiler/lexer.go`

Здесь реализован лексический анализ. `lex` идёт по исходной строке, ведёт
номер строки и столбца, распознаёт многосимвольные операторы и проверяет
незакрытые блоковые комментарии. Результат — срез `token`, завершённый
специальным токеном конца файла.

### `internal/compiler/ast.go`

Здесь описано синтаксическое дерево. В файле есть типы выражений:
константа, переменная и бинарная операция; а также типы операторов:
`read`, `write`, присваивание, условия, циклы, блок и `skip`. Эти структуры
не экспортируются: они нужны только парсеру и генератору.

### `internal/compiler/parser.go`

Здесь реализован рекурсивный нисходящий парсер. Методы `parseStatement` и
дочерние методы разбирают операторы языка. `parseExpression` использует
приоритеты из `precedence`: от низкого `!!` к высокому `*`, `/`, `%`.
Операторы одного приоритета группируются слева направо. Парсер также
преобразует `elif` в вложенный узел `ifStatement`.

### `internal/compiler/generator.go`

Здесь AST преобразуется в инструкции стековой машины. `compileExpression`
сначала генерирует левый операнд, затем правый и `BINOP`; поэтому порядок в
стеке соответствует интерпретатору. `compileStatement` обрабатывает простые
операторы. Для ветвлений и циклов он создаёт уникальные метки.

`while` использует переход к проверке условия, тело и `JNZ` обратно в тело.
`do ... while` сначала выполняет тело, затем проверяет условие. `for` сначала
генерирует инициализацию, затем переводится в `while`, в теле которого после
пользовательского тела выполняется выражение обновления. `if` использует `JZ`
для перехода к альтернативе и `JMP` для пропуска альтернативы после истинной
ветви.

### `internal/compiler/compiler_test.go`

Это интеграционные тесты компилятора. Они читают все примеры исходного языка
из `tests/testdata/sources.json`, компилируют их, передают полученный JSON
существующему интерпретатору и сравнивают его результат с ожидаемым. Отдельный
тест проверяет, что компилятор отвергает несколько вариантов неверного
синтаксиса.
